# 1. 选择 Network TON-IoT 数据

我想比较原始特征、特征选择和 PCA 对入侵检测的影响，所以先参考了《Optimizing IoT intrusion detection system: feature selection versus feature extraction in machine learning》。这篇论文使用的是 461,043 行的 Network TON-IoT 训练测试数据。我的实验重点是比较已有的网络流量特征，因此没有选择从原始 PCAP 重新提取特征，也没有改用 NetFlow 转换版。

我沿着 [UNSW 官方数据说明](https://research.unsw.edu.au/projects/toniot-datasets)找文件。最先拿到的 `train_test_network.csv` 只有 211,043 行、44 列，与[论文所述](https://link.springer.com/article/10.1186/s40537-024-00892-y)的规模不符，所以没有把它作为本次实验的主数据。我还查到一个早期官方 CloudStor 入口，但该服务已经停用，目前没有找到能直接核验为论文所用版本的官方文件。

后来我找到一个 [Hugging Face 公开镜像](https://huggingface.co/datasets/kunal0902/network-intrusion-iot/tree/main)。其中的 `Train_Test_Network.csv` 有 461,043 行、45 列，正常流量 300,000 行、攻击流量 161,043 行，与论文的关键统计一致。我核对了桌面和项目 `data/raw/` 中的文件，两者 SHA-256 相同，于是决定先用这份数据开展实验。

这份文件来自镜像，不能仅凭行数和类别分布证明它与论文原文件完全相同。因此我会注明数据来源，不把它写成“官方原版”，也不宣称严格复现论文。

# 2. 核对原始文件和已有笔记

我先进入 WSL 的 `/home/wyh/projects/cybersecurity_learning`，查看 Git 状态和现有目录。四份 notebook 是未跟踪文件，`process.md` 已有本地修改，所以我没有把它们当成可覆盖的空白项目。01 已有用户实际运行的输出，02 至 04 还是空笔记。我把 01 的代码、结论和输出依次读过，发现它先读取了 1,000 行样本，后面的质量检查却使用尚未定义的 `df`，需要补齐全量读取步骤。

我接着比较 WSL `data/raw/Train_Test_Network.csv` 与桌面同名文件。两份都是 69,861,203 字节，SHA-256 均为 `65d5465df1809b984fd10e4703bc9c012d1aefd11803773856364216f0a3520d`，都有 461,043 行、45 列和 11,071 条完全重复记录，字段顺序与标签分布也相同。我据此确认 `raw` 仍是未去重副本，不需要从桌面替换，也不在原文件上写入处理结果。

# 3. 从数据探索走到输入设计

我先修正 01 的全量读取顺序，再运行已有的标签、横杠、重复行检查。去掉完全重复行后，内存中的数据有 449,972 行，其中正常 288,929 行，攻击 161,043 行。我又查看 `weird_name`，出现它的 1,294 行中有 1,291 行 normal 和 3 行 ddos，因此没有把它当作攻击标签。主要流量数值有长尾，我先保留原值，避免在还没有划分数据前依据极值删行。我用全量去重数据画类别数量图，再对每类各抽 5,000 行画源端字节与连接时长的对数分布图，对数只用于显示。

我重新对照论文第 10 至 12 个 PDF 页面。论文去掉时间戳、源和目标 IP、源和目标端口，剩 38 个输入字段。论文把横杠解释为网络字段不可用，对高基数字段做是否可用的二值化，对指定类别字段做独热编码。我据此编写 02，保留 `weird_addl` 和 `weird_notice`，撤下旧草稿中直接删除 `weird_notice` 的做法。旧草稿中的 Chi-square 与 100,000 行预跑数字也不再作为正式方法或正式结果。

# 4. 划分并验证数据准备

我先按论文的 80 比 20 比例用 `label` 分层，再用训练集拟合独热编码器和 Min-Max 缩放器。实际训练和测试分别有 359,977 行和 89,995 行，攻击比例接近。字段分组为 14 个数值列、10 个二值列和 14 个类别列，训练集拟合后的输入为 91 维。论文写的是 77 维，我保留了本文件实际出现的类别，并把差异写入方法对照文件，没有为了凑数删列。缩放后的训练和测试都没有非有限值，测试集中有 2 个值超出训练范围。

在拟合编码器前，我按当前输入组合计算训练和测试的指纹。89,995 条测试记录中有 54,061 条在编码前与训练记录具有相同的输入指纹。初次使用 `float32` 编码时重叠数多出 17 条。我发现这是大数值列降低精度后合并输入，于是改用 `float64` 重新运行。编码前后的重叠数现在均为 54,061 条。这让我决定保留论文式分层划分作为对照，同时把按输入组合隔离的划分列为后续敏感性检查。它是本项目的改进，不是论文原实验，也不能把旧的 10 万行预检分数写成这次实验的结果。到目前为止，我只运行了 01 和 02 的数据处理，没有运行特征选择、PCA 或分类器。

# 5. 回看 01 并接上 02

完成数据准备后，我回看 01 是否真的解释了为什么要做 02。我保留了先核对文件和标签、再检查横杠与重复记录、最后观察 `weird` 和数值分布的顺序，并在开头写清数据来源与本笔记的范围。标签交叉表支持正常与攻击二分类，横杠在 DNS、SSL、HTTP 字段中的分布让我不把它们统一填成零。11,071 条整行重复都属于 normal，所以我先在内存中去重，但我也明确记下整行去重无法保证删除环境标识后的输入组合不重复。

我补查了 `weird_addl`，在去重后的数据中看到 753 个非横杠值，确认这组字段不能凭名称推断为攻击。数值审计显示源端字节有很长的尾部，图中两类在零附近聚集且互有重叠，mitm 的行数也明显少于其他攻击类型。这些观察只能提出缩放和评价的注意点，不能在 01 推断模型表现。因此 02 从原始文件独立重做去重，剔除标识并检查输入组合，再用 80 比 20 分层划分和训练集拟合的编码、缩放继续实验。01 是形成处理依据的数据探索，02 是落实这些决定的数据准备，两本笔记不靠共享内存变量衔接。
